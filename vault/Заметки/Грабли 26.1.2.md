# Грабли 26.1.2

Всё, на чём можно потерять время, потому что интернет и обучающие видео описывают предыдущие
версии. Собрано по итогам реальной отладки, каждый пункт проверен на живой сборке.

> [!warning] Общее правило
> Для 26.x проверяй факты в maven и исходниках, а не по памяти и не по гайдам. Экосистема
> сильно поменялась между 1.21.x и 26.x.

## 1. Yarn больше нет, код на маппингах Mojang

Последний Yarn — 1.21.11. Для 26.x его не выпускают. Пиши мохмаповские имена:

| Yarn (устарело) | Mojang (26.x) |
| --- | --- |
| `MobEntity` | `PathfinderMob` |
| `World` | `Level` |
| `ResourceLocation` | `Identifier` |

`ResourceLocation` → `Identifier` — это переименование **внутри** мохмапа, а не разница Yarn/мохмап.
Импорт теперь `net.minecraft.resources.Identifier`.

## 2. `modImplementation` не существует

Симптом: `Could not find method modImplementation()` на этапе конфигурации.

```groovy
// ❌ падает
modImplementation "com.geckolib:geckolib-fabric-26.1.2:5.5.2"

// ✅
implementation "com.geckolib:geckolib-fabric-26.1.2:5.5.2"
```

Loom 1.17 сам определяет, что зависимость — мод, и ремапит её. Проверено: GeckoLib грузится
в игре именно как мод, в списке модов Fabric Loader.

## 3. GeckoLib: и группа, и пакет, и папки ассетов

Группа и Java-пакет — `com.geckolib` (было `software.bernie.geckolib`).

**Самое коварное — папки ассетов.** GeckoLib 5.5 сканирует:

```
assets/<namespace>/geckolib/models/...
assets/<namespace>/geckolib/animations/...
```

Старые `geo/` и `animations/` в корне **не работают и не пишут ошибку** — модель просто не
находится. Проверка одна: в логе клиента должна быть строка

```
[GeckoLib] Loaded N models and N animations from resources
```

Если N нулевое или строки нет — пути неверные. Текстуры при этом остаются на обычном месте,
в `textures/entity/`.

## 4. `EntityRendererRegistry` устарел целиком

Класс из Fabric API помечен `@Deprecated` полностью. Замена — ванильный метод, открытый
транзитивным access widener'ом:

```java
// ❌
EntityRendererRegistry.register(ModEntities.SILVERLEOS, SilverleosRenderer::new);

// ✅
EntityRenderers.register(ModEntities.SILVERLEOS, SilverleosRenderer::new);
```

## 5. Java 25 не обязательно ставить руками

Toolchain + `foojay-resolver-convention` скачивают JDK сам. Подробнее — [[Стек и версии]].

## 6. Разовый сбой при скачивании нативов LWJGL

Один раз `runClient` упал на TLS-хендшейке при загрузке `lwjgl-glfw-natives-windows` с
`libraries.minecraft.net`. Хост при этом был доступен, повторный запуск прошёл нормально.

Вывод: если `runClient` падает на скачивании нативов — сначала просто повтори, это не поломка
проекта.

## 7. Убитый клиент возвращает код 4294967295

Если останавливать дев-клиент принудительно, Windows возвращает `4294967295` (это `-1`). Это не
краш мода, а нормальный код для убитого процесса.

Отдельно: `gradlew` — только обёртка. Реальный клиент это дочерний JVM, и он **переживает**
остановку обёртки. Гасить надо именно процесс клиента, иначе он останется висеть в памяти
на пару гигабайт.
